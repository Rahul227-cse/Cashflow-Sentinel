# CashFlow Sentinel

An explainable cash-flow early-warning prototype for Indian MSME suppliers. It ranks invoice collections and surfaces **suspected discrepancies** from synthetic data; it does not prevent fraud, guarantee payment, or use a trained ML model.

## Exasol-first setup

The API defaults to Exasol and does not silently substitute SQLite if Exasol is unavailable. The existing Exasol Personal instance is expected to be reachable at `127.0.0.1:8563` from Windows. Create a local ignored `.env` by copying `.env.example`, then replace only `EXASOL_PASSWORD` with the value held in the existing WSL deployment's `secrets.json`. Do not commit `.env`.

For the local Exasol Personal self-signed certificate only, set `EXASOL_INSECURE_TLS=true` in the ignored `.env`. Do not use that setting with a remotely accessible or production database; install and verify a trusted certificate instead.

Initialize the isolated `CFS_DEMO` schema and deterministic synthetic rows. This is idempotent: it merges only the application’s stable synthetic IDs and does not reset other Exasol schemas.

```powershell
pip install -r backend/requirements.txt
python -m backend.seed
python -m flask --app backend.app run --port 5000
```

In another terminal:

```powershell
cd frontend
npm install
npm run dev
```

The React app reads the Flask API at `http://localhost:5000/api`. Verify the selected store with `GET /api/health`; a correctly configured demo returns `"store": "exasol"`.

### Test-only SQLite

SQLite remains available only for isolated test runs and is never an automatic fallback:

```powershell
$env:CASHFLOW_STORE='sqlite'
$env:DATABASE_URL='sqlite:///test_cashflow.db'
python -m backend.seed
```

The SQLite files (`cashflow_sentinel.db` and `test_cashflow.db`) can be removed later if no longer needed; they are not used by an Exasol-configured API.

## Scoring

Risk is a transparent 0–100 heuristic: customer historical lateness (up to 35), invoice overdue/due proximity (up to 30), balance size (up to 20), and customer late-payment rate (up to 15). Scores ≥70 are high, ≥40 medium, otherwise low. Collection priority combines risk, overdue days, and open balance. These are decision-support signals only.

## API

- `GET /api/dashboard`
- `GET /api/invoices?query=&status=&risk=&page=&page_size=`
- `GET /api/invoices/<id>`
- `GET /api/alerts?severity=`
- `GET /api/collections`
- `GET /api/risks`
- `POST /api/reconciliation/run`

Example: `curl http://localhost:5000/api/health` returns the active store without credentials. The React application uses the dashboard, invoices, alerts, and collections endpoints; it contains no database configuration.

## Verification

```powershell
pytest backend/tests -q
cd frontend; npm run build
```

The Exasol integration test is intentionally skipped—with an explicit reason—when the local credentials are absent. With `.env` configured, run `pytest backend/tests/test_exasol_integration.py -q` to execute a genuine seed and `SELECT COUNT(*)` against Exasol.

## Data and limitations

All records are deterministic synthetic fixtures generated by `backend/seed.py`. Exasol DDL is version-controlled at `backend/sql/exasol_schema.sql`. No external data sources, paid APIs, or cloud services are used. This prototype is decision support only: it does not prevent fraud, guarantee payment, or use a trained ML model.

## GitHub readiness and cleanup

`.env`, SQLite databases, Python caches, virtual environments, frontend build output, and `node_modules` are ignored. Retain `frontend/package-lock.json` for reproducible installs. Do not publish before checking `git status`, searching for secrets, and confirming the live Exasol integration test passes.

After a preserved backup or GitHub push, possible cleanup candidates are the generated SQLite test databases, `.pytest_cache`, `__pycache__`, `frontend/dist`, and `frontend/node_modules`. Do not remove the selected Windows project, the original WSL project, Exasol deployment, or system runtimes without a separate review.
